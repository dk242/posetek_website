## Persistence

- `players/{playerId}/aiAnalysisReviews/{reviewId}`: immutable complete review, authoritative original from `aiAnalysisRuns`, source hash/provenance, edited feedback, frame annotations, private notes, explicit dataset approval, reviewer identity and server timestamp.
- `players/{playerId}/aiAnalysisReviewHeads/{single_repId|comparison_comparisonId}`: latest revision/source-job pointer. Saving requires an exact base revision and the same current generation. Old reports without immutable history require regeneration.
- `players/{playerId}/aiAnalysisCorrections/{single_repId|comparison_comparisonId}`: optional athlete projection containing only feedback, annotations, source-job and revision identity. Clients must match `sourceJobId` to the current report before displaying it. Saving with publication disabled removes this projection.
- Manual single-kick reviews are supported when no generated result exists. The viewer captures Storage generation and MD5 identities before and after loading pose, metadata and reprocessing JSON. The server rejects source drift, reads those exact generations with bounded JSON downloads, and preserves the source rep, artifact SHA-256/generation/MD5, recorded FPS/frame count/image dimensions and exact annotated pose frames plus one neighbor on either side. No video is downloaded by this callable. Unverifiable sources remain authorable and publishable, with dataset approval unavailable. A changed source on a later manual review requires an explicit fresh draft; generating an analysis also creates a different source and never silently rebases labels.

Canonical Firestore rules are maintained by the root integration task: review/history reads are admin-only, correction reads follow authorized athlete access, and all client writes to these collections are denied. Rules and callables must be deployed before using the production workspace.

## Dataset export

`adminExportAnalysisReviews({playerIds, cursor})` accepts at most 100 athlete IDs, returns at most 25 examples and 5 MB per page, and supplies `nextCursor` until complete. The UI downloads JSONL containing approved current review revisions only. A newer unapproved revision excludes earlier approved revisions on subsequent exports. Each candidate's head, review and run are reread transactionally; a concurrent approval withdrawal aborts the export. Export retains `input: {context, toolEvidence}`, original result, provenance, expected ordered feedback and evidence IDs, annotations and private notes. Source hashes use recursively sorted map keys and normalized timestamps. Temporal citations require `evidence.rows[].eligible === true`; bilateral citations require `differences[].comparable === true`.

The stable split is `SHA256('kick-review-v1:' + playerId)`, first eight hexadecimal digits interpreted as an integer: remainder zero modulo five is `evaluation`; every other athlete is `train`. All examples for an athlete receive the same split. This creates a review dataset; it does not perform automatic model training or claim improved technique accuracy. Human priority corrections provide the regression expectations.
